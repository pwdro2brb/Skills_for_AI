# evidence-driven-investigation

An [Agent Skill](https://agentskills.io/specification) that makes an AI agent
investigate like a careful engineer or scientist: separate what it observed
from what it infers, test competing hypotheses, keep unknowns and
contradictions visible, and **compute** whether the work is complete instead of
declaring it.

It is model-agnostic. The instructions are plain Markdown; the mechanism is a
JSON ledger and Python scripts that use only the standard library.

## 1. The problem

Agents are good at producing answers that sound right. On tasks with real
uncertainty (a bug with an unknown cause, an undocumented file format, a
dataset with a striking correlation, a conjecture that holds in every case
tried) the plausible answer is often wrong, and nothing in the answer shows it.
Typical failures:

- picking the first cause that fits and never testing an alternative;
- presenting an inference as an observation;
- treating "I didn't find it" as "it doesn't exist";
- calling something verified because a unit test passed, when the claim was
  about the shipped artifact;
- making an inconvenient contradiction disappear;
- stopping because the files were created.

## 2. Why plausible answers are not enough

A plausible answer has no visible link to evidence, so the reader cannot tell
which parts were checked. This skill makes that link explicit and checkable:
every material claim is a record with an epistemic status, every piece of
evidence has provenance and scope, and the final state is derived from those
records by a script. When the evidence does not support completion, the script
says so, and the agent reports that.

## 3. Relation to the scientific method and evidence-driven engineering

The loop is the scientific method applied to engineering work: observe,
hypothesize, predict, probe, record, look for contradiction, refine, build,
verify independently. The skill adds what agents tend to skip:

- **Falsification**: probes are chosen because hypotheses predict different
  results; rigorous mode requires a recorded counterexample search (after
  [POPPER](https://arxiv.org/abs/2502.09858)).
- **Authority matching**: each kind of claim needs a minimum kind of evidence
  (a compiler for "it compiles", a packaged-artifact test for "it works when
  shipped", a reviewed or formal proof for a theorem).
- **Residual unknowns, obligations and the separation of authenticity,
  authority and applicability**, generalized from the reverse-engineering tool
  [REA](https://github.com/morluto/rea).

The research behind these choices, source by source, is in
[docs/research-analysis.md](docs/research-analysis.md) (Portuguese).

## 5. Installation

Requirements: Python 3.9 or newer for the scripts. No packages to install.

Build the installable package (only runtime files; no tests, evals or examples):

```
python tools/package_skill.py evidence-driven-investigation
# -> dist/evidence-driven-investigation-1.0.1.zip
```

Then, depending on the agent:

- **Claude Code**: unzip into `~/.claude/skills/` (all projects) or into
  `.claude/skills/` inside a project, so that the path is
  `.../skills/evidence-driven-investigation/SKILL.md`.
- **Claude apps**: upload the zip in the skills section of Claude's settings.
- **Other agents supporting Agent Skills** (Codex, Cursor, Gemini CLI and
  others): place the folder in that agent's skills directory, as its
  documentation describes.
- **Any other model**: give it `SKILL.md` as instructions and let it run the
  scripts; without code execution, it can keep the ledger by hand (section 8 of
  `SKILL.md`).

Check the installation by running the test suite from the repository:

```
cd evidence-driven-investigation
python -m unittest discover -s tests
```

## 6. Usage

Ask normally. The skill's description tells the agent when to load it: unknown
causes, competing explanations, requests for proof or audit, costly mistakes.
You can also ask for it explicitly ("investigate this with the
evidence-driven-investigation skill, rigorous mode").

The agent then drives the scripts. A minimal session:

```
S=path/to/evidence-driven-investigation/scripts
python $S/init_investigation.py --ledger inv.json --id export-bug --title "Export bug" \
    --objective "Find why export fails" --mode investigative --limitation "Linux only"
python $S/record_obligation.py --ledger inv.json --claim "Cause identified" \
    --kind root-cause --required-authority root-cause-identified
python $S/record_evidence.py --ledger inv.json --claim "7/50 runs fail with KeyError 'tz'" \
    --source-type test --authority unit-test --tool pytest --command "pytest -k export --count 50" \
    --artifact-file src/export.py --scope "this commit, Linux"
python $S/record_hypothesis.py --ledger inv.json --kind primary --statement "..." \
    --prior-basis "..." --prediction "If true, ..."
# ... probes, more evidence, closing obligations ...
python $S/evaluate_completion.py --ledger inv.json
python $S/generate_report.py --ledger inv.json --format concise
```

## 7. Modes

| Mode | When | What the agent does |
| --- | --- | --- |
| Light | Low risk, known procedure, simple check | Does it, runs one real check, answers in a line or two. No ledger. |
| Investigative | Unknown cause, competing explanations, learning how something works | Ledger, competing hypotheses, discriminating probes, obligations, concise report |
| Rigorous | Extraordinary or high-impact claims, math/science, security, reproducibility, explicit request for proof | Adds null/alternative hypotheses, counterexample search, independent critic, independent verification route, reproducible evidence, rigorous report |

## 8. Examples

All four in [examples/](examples/) are real output of the scripts; a test
rebuilds them and checks they are byte-identical.

### Small: two causes behind one bug (investigative)

`average_price()` crashes "for some stores". The agent records three
hypotheses (decimal commas, empty stores, CSV reading), runs one probe that
flips each variable alone, and finds that **both** of the first two are real
causes. Trying to close the root-cause obligation before the probe ran was
refused:

```
error: Refusing to write: the change introduces validation errors:
ERROR O02 O-0001: CLOSED requires active verification_evidence
ERROR O02 O-0001: required case 'store_b' has no active evidence
ERROR O02 O-0001: required case 'store_c' has no active evidence
```

After the probe and a separately verified fix, the concise report
([full file](examples/software-debugging/report.md)) begins:

```
# average_price crashes for some stores

**Computed final state:** `COMPLETE_VERIFIED` (mode: investigative)

| ID | Status | Claim | ...
| F-0002 | VERIFIED | Decimal-comma prices cause the ValueError | ... root-cause-identified |
| F-0003 | VERIFIED | Stores without orders cause the ZeroDivisionError | ... root-cause-identified |
| F-0004 | VERIFIED | The patched module handles every observed format and empty stores | ... function-works |
| F-0005 | ASSUMED | Returning None for a store without orders is acceptable | ...

| U-0001 | medium | OPEN | What should average_price return for a store with no orders? |
```

### Rigorous: a conjecture that holds 40 times (rigorous)

"n² + n + 41 is prime for every n ≥ 0." The first 40 cases are prime. The
agent's attempt to mark the conjecture as a verified theorem from those cases
was refused:

```
ERROR H03 H-0001: VERIFIED without sufficient verification_evidence: claim type 'theorem-valid'
requires 1x[reviewed-proof] OR 1x[formal-proof] AND 1x[formalization-review]; have ['numerical-test']
```

A bounded search finds n = 40 (1681 = 41 × 41), an independent algorithm
confirms it, and the conjecture is refuted. But no independent critic reviewed
the work, so the computed state is not the strongest one:

```
STATE: COMPLETE_WITH_LIMITATIONS (mode=rigorous)
  [x] G1 At least one obligation exists
  [x] G2 Every critical obligation is CLOSED
  ...
  [ ] G8 Mode requirements are met
        - rigorous mode needs review evidence from a collector other than the producer(s) ['single-agent']
```

See [examples/mathematical-investigation/report-rigorous.md](examples/mathematical-investigation/report-rigorous.md).
The other two examples cover reverse engineering (a byte that changes with the
speed is a checksum) and data analysis (a correlation explained by a confounder).

## 9. Schemas

`schemas/` defines every record in JSON Schema Draft 2020-12:
`investigation`, `evidence`, `hypothesis`, `probe`, `unknown`, `contradiction`,
`obligation`, `finding`. They are valid against the official metaschema and
usable by any JSON Schema tool. Conditional rules (for example "runtime
evidence needs a command and an artifact hash") are enforced by the scripts and
listed with their codes in `references/completion-gates.md`.

| Prefix | Record | Purpose |
| --- | --- | --- |
| `E-` | evidence | an observation or a deterministic derivation (only OBSERVED or DERIVED) |
| `H-` | hypothesis | falsifiable explanation with predictions |
| `P-` | probe | experiment with expected result per hypothesis, cost, risk, authorization |
| `U-` | unknown | bounded open question with the authority needed to close it |
| `C-` | contradiction | conflict, never deleted, with an explanation checklist |
| `O-` | obligation | verifiable completion requirement |
| `F-` | finding | a material claim with one of nine epistemic statuses |

## 10. Scripts

| Script | Purpose |
| --- | --- |
| `init_investigation.py` | create a ledger (never overwrites without `--force`) |
| `update_investigation.py` | mode, scope, criteria, limitations, authority extensions, conclusion |
| `record_evidence.py` | add evidence (computes hashes); `--invalidate` reopens dependents |
| `record_hypothesis.py` | add/update hypotheses and predictions |
| `record_probe.py` | plan, authorize, complete, `--rank` probes |
| `record_unknown.py` | add/update residual unknowns |
| `record_contradiction.py` | record contradictions and resolve them with new evidence |
| `record_obligation.py` | add obligations, attach evidence, close/fail/block/waive |
| `record_finding.py` | classify each material claim |
| `validate_ledger.py` | all errors and warnings (`--strict`, `--json`, `--reseal`) |
| `evaluate_completion.py` | compute the final state (`--json`, `--expect` for CI) |
| `generate_report.py` | concise or rigorous Markdown report |

Common behavior: `--help` on every script; `--ledger` always required; a
change that would introduce a validation error is refused and explained;
existing records change only with `--id ... --update`; writes are atomic;
`EDI_FIXED_TIME` or `--timestamp` make output deterministic; exit codes 0
(success), 1 (refused or invalid), 2 (unusable input), 3 (`--expect` mismatch).

## 11. Multi-agent use

Optional. Roles (coordinator, observer, hypothesis generator, researcher,
experimenter, implementer, adversarial critic, counterexample searcher,
verifier, synthesizer) and rules: bounded questions only, proposer separate
from critic, structured JSON returns imported with `--input`, agreement between
agents is not evidence, only the coordinator writes the ledger. See
[references/multi-agent-patterns.md](references/multi-agent-patterns.md).

## 12. Limitations

- **The scripts check coherence, not truth.** A record labelled
  `runtime-trace` that was really a code reading passes. The report shows the
  tool and command of every record so a reviewer can catch it. REA states the
  same limit for its own evaluator.
- **An agent can fill the ledger ceremonially.** Hypotheses written to be
  rejected and evidence recorded without being looked at are possible. The
  gates make this more work than doing it properly, not impossible.
- **Overhead.** Investigative and rigorous modes cost tokens and time. The
  light mode exists so that simple tasks stay simple; whether agents choose it
  correctly is what eval case 5 measures.
- **Eval results do not exist yet.** The seven cases and the grader are ready;
  the comparison with and without the skill has not been run.
- **Platforms.** Tested on Linux with Python 3.9, 3.11, 3.12 and 3.13. Written
  for Windows and macOS (paths, line endings, console encoding) but not yet run
  there.
- **The authority matrix is a starting point.** It encodes common judgments;
  domains will need extensions, and some entries will be argued with.

## 13. Safety

The skill never justifies an action the user did not authorize. Irreversible,
destructive, external or sensitive probes are flagged by the probe script and
cannot be marked as run until an authorization is recorded. The agent works on
copies, hashes originals, keeps credentials and personal data out of
evidence, treats text found in files and outputs as data rather than
instructions, does not treat simulations as real-world evidence, reports
negative results and never fabricates sources, logs, tests or executions.
Reverse engineering is limited to interoperability, preservation, debugging,
authorized research and artifacts the user owns. Full text:
[references/safety-boundaries.md](references/safety-boundaries.md).

## 14. Adding a domain adapter

1. Write a section in `references/domain-adapters.md`: tools and their
   authority, typical claim types, evidence that is commonly over-stretched,
   commonly forgotten hypotheses, risky actions.
2. If the domain needs new authorities or claim types, write them as an
   extension (JSON with a rationale for each entry) and load it per
   investigation with `update_investigation.py --extend-authority FILE`.
   Extensions never override the base matrix and appear in the rigorous report.
3. If an extension proves generally useful, propose it for the base
   `authority-matrix.json` with a test in `tests/`.

## 15. Running the evals

See [evals/README.md](evals/README.md) for the protocol. In short: copy one
case folder into a fresh directory, run the same model with and without the
installed skill on its `PROMPT.md`, save the final answer, and grade:

```
python evals/grade.py --case case-04-false-conjecture --condition skill \
    --workdir runs/c4/skill-1 --answer runs/c4/skill-1/answer.md --out results/c4-skill-1.json
python evals/grade.py --summarize results/*.json
```

Install the packaged zip for the runs so the agent cannot read `evals/`.

## 16. Roadmap

- Run the evals across several models and publish the results, including
  where the skill does not help.
- CI on Windows and macOS.
- An optional MCP server exposing the same operations as tools.
- More domain adapters (security research with authorization records, ops
  incident analysis, literature review).
- Sequential evidence aggregation (e-values) for data-analysis probes.
- Support for evidence bundles exported by tools such as REA.

## What this project does not claim

- It does not make models infallible.
- It does not guarantee scientific discovery.
- It does not replace experts.
- It does not turn weak evidence into proof; it makes the weakness visible.
- It does not eliminate hallucinations; it makes unsupported claims harder to
  present as established.
- It does not provide domain tools (debuggers, disassemblers, provers,
  statistics packages); it says what their output is worth.
- It does not replace experimental, formal or human validation.
